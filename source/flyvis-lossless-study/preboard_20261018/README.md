# 候选⑪正式上板前准备

目标：正点原子领航者 ZYNQ-7020；冻结候选 `hole_pipeline_20261016/soc_r2`，完整45,669节点、1,513,231连接、严格FP32、100MHz，核心周期2,201,418，理论22.01418ms/步。

本包用于首次完整单步验证。准备阶段只在PC校验、打包并测试模拟接口，**不连接板卡**。CPU mock PASS 不是实板 PASS；旧候选71.63ms的BIT/HWH/XSA不与本包混用。实际绘图、摄像头、GPU、485步长跑、功耗实测不由本入口启动。

## 到板旁之后

确认使用此前确认的领航者7020板，供电和连接正常，并释放当前其他工程/Notebook/服务对板卡的占用。不要为本实验升级PYNQ、系统镜像或更换启动文件；准备目标是历史记录中的PYNQ2.7/Python3.8，当前版本须在执行时重新读取。

将本ZIP解压至板端一个**新的独立目录**，保留原工程。确认本次已获得板卡独占窗口和加载授权后，在该目录执行一次：

```bash
python3 -B board_check.py --execute --exclusive-board-window
```

这两个参数分别表示“实际执行”和“操作者已释放独占板卡窗口”，不是定时任务或长期授权。没有参数时：

```bash
python3 -B board_check.py
```

只检查本地文件，既不导入PYNQ，也不连接/操作板卡。准备阶段只执行这个默认分支。

## 实际执行范围

1. 校验包内文件、固定BIT/HWH身份、目标器件和AXI地址；执行时不重新运行神经模型。
2. 读取当前PYNQ版本、设备树、已有overlay记录/文件身份、FCLK和进程/端口占用，保存`board_before.json`。这是运行时元数据，不是对旧PL功能的测试。遇到其他相关kernel/进程、5771/5772监听或未知元数据时停止；不停止别人的进程。
3. `Overlay(..., download=False)`先解析新HWH并检查网络地址，之后**只调用一次**`download()`，它会应用HWH时钟设置并配置PL。当前HWH与旧PYNQ解析兼容性在真实运行前仍属未验证；失败就保留输出。
4. 读回FCLK0，应为100MHz；读取新PL的节点数、连接数和接口版本，必须匹配45,669/1,513,231/0x00110002。通过前不写神经控制寄存器。
5. 发出一次完整状态恢复，读回并逐位比对**全部45,669个初态**。不是只检查若干节点或checksum。
6. 写入721个原始FP32输入字，发出**恰好一个STEP**，以5秒等待期限检查完成计数、边数、节点数和故障标记。
7. 读回全部45,669个FP32状态，保存原始二进制并逐位比较首步参考；检查完成步数1、核心周期2,201,418。保存输入传输、STEP调用等待、完整读回的独立耗时。STEP调用时间包含轮询开销；真正核心时间用周期计数/所读时钟计算。
8. 通过后留下`PASS_BOARD_ONE_STEP_ALL_STATES`和本次原始状态。网络保留step1状态，不再恢复，不自动开始第二步或显示。之后才接已有`frame_stepper.py`的一步一帧回调；本包不改动②⑦⑨的GUI/摄像头/协议。

实际加载会覆盖当前PL配置，因此必须先由操作者释放并确认本次窗口。检查与加载之间仍存在共享板竞争的可能，单靠端口扫描不能保证独占。输入/读回和Python耗时不在22.01418ms理论核心时间内。

## 错误与回退

超时、时钟/身份/状态不符或中断时保存`result.json`及`events.jsonl`，立即停止。开始硬件操作后的失败标记`IN_DOUBT_DO_NOT_REPEAT_OR_RESET`，**不自动重试STEP、不自动复位、重载或回退旧工程**。一次STEP可能已完成，不能把重试当作无副作用。

原来BIT/HWH路径和哈希由运行前快照保留，旧工程文件不覆盖、不删除。恢复旧工程需要另行确认原文件和操作范围；重新加载旧位流本身不能凭空恢复先前正在运行的神经状态。快照失败或所有权不明时不加载新位流。

## 离线准备验收

准备脚本只核对选定源文件、构造新包、从ZIP独立解压，并在解压副本执行轻量CPU mock测试。测试覆盖全状态读取、最后一个神经元单bit差异、初态错误、占用、时钟/版本错误、超时不重试、周期错误和Python3.8语法。mock输出明确标为`CPU_MOCK_ONLY`，不写实板PASS。
