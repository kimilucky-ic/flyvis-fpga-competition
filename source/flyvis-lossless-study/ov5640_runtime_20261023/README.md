# OV5640 AXI IIC与采集输入绑定：CPU验证候选

2026-10-23；完整45,669节点/1,513,231连接、严格FP32及100MHz目标不变。新代码仅在本目录，既有RTL、BIT/HWH和其他工作线未修改。没有硬件访问、GPU、Vivado或摄像头操作。

## 接口与验证结果

`iic_adapter.py`对接PYNQ2.7的`send(address,data,length,option)`、`receive(...)`、`wait()`，不自动创建硬件对象。地址固定为7位0x3c，寄存器地址高字节在前。读寄存器使用写地址后STOP，再START读取，与官方SCCB代码一致。检查每次实际传输长度；短传输、异常、等待超时或迟到返回都会锁定失败状态，后续调用不再触发总线。初始化程序沿用上一候选248笔写入，不重新解释其寄存器表。

API依据官方版本源码： https://raw.githubusercontent.com/Xilinx/PYNQ/v2.7.0/pynq/lib/iic.py 。该API调用底层C发送/接收，未提供Python超时参数。本适配器只能检测返回后的耗时，**不能中断永久阻塞的C调用**。CPU测试里的迟到返回不是物理总线硬超时证明；正式板端运行前须补充底层有界事务/看门狗方案，不能另启线程后放任旧事务继续并自动重试。

`CapturePool`提供FREE→WRITING→READY→HELD→FREE所有权模型及代次令牌。只有FREE或未选中READY缓冲可再授予采集；持有帧和正在写入帧不可覆盖；全占用则拒绝新采集。完成帧进行不可变字节拷贝，错误长度/过期完成令牌锁定失败。实际VDMA必须只使用grant()授予的缓冲，确认完成且不再写该缓冲、检查DMA错误/帧长度并执行cache invalidate及屏障后，才调用complete()。**本轮未接真实VDMA；把此模型套在仍会循环覆盖的VDMA外面不构成保护。**

`BoundSteps`只接收已有控制器advance和已解码记录fetch回调，不创建第二套板卡控制器。每步依次：

1. 独占取得完整相机帧，生成721项有限[0,1] FP32输入。
2. 将原始帧、2884字节输入及源帧号/时间戳/神经步号/SHA写入独立步目录，flush+fsync，并写PREPARED。
3. 使用同一输入位串调用一次advance。检查连续神经步号和发布序号。
4. 保存实际发布输入及完整182676字节状态，再检查输入逐位一致、步号一致及状态长度，写COMMITTED。完整状态数值的oracle验收继续由既有审计流程承担，此层不宣称通过。
5. 成功后释放采集帧；错误则锁定失败，保留帧租约、所有已落盘记录和能写入的IN_DOUBT，不自动STEP/重置/重试。记录容量满时在下一STEP前停止。

目录存在时拒绝复用。COMMITTED是输入绑定完成，标记明确为INPUT_BINDING_ONLY_FULL_STATE_ORACLE_PENDING，不是全状态数值PASS。fsync行为仍需板端文件系统/断电恢复验证；当前无自动恢复或续跑入口。当前先用同步保存保障证据，不宣称日志IO不会影响步率；显示不参与此锁或STEP回调。

## 测试

`test_runtime.py`共12项CPU测试通过，CPU.log与CPU_RESULT.json记录最终结果。使用原NumPy预处理生成640×480合成帧0/4/9的真实721项输入，绑定连续神经步0/1/2，所有输入字节精确核验。状态使用显式零填充fixture，未运行神经模型。完整保留3步raw frame/input/actual input/state/metadata，路径由CPU_RESULT给出。

并发测试在持有首帧期间完成99次模拟采集，旧帧及其内容未改变；最新源帧可跳过旧的未选中源帧，但已提交神经步不丢。测试同时覆盖全占用拒绝采集、过期令牌、短帧、总线异常/短发送/短接收/迟到返回/等待失败、非法输入、STEP超时、发布序号/输入损坏/状态长度错误、STEP之前和之后磁盘失败、不重试及不释放不确定租约。并发生产者异常通过Future返回到测试主线程。

最初测试使用系统临时目录，清理遭本机沙箱权限拒绝；FIRST_CPU.log/JSON保留失败。随后仅更改测试证据目录为本候选内独立保留目录，不删除临时目录、不修改产品行为。后续修正并发测试异常传播后重新运行12项，通过。

BASELINE_CHECK.json确认四份神经旧版1459个成员及两个相机候选110个成员全部SHA一致。MANIFEST_SHA256.json封存本候选。没有新增Skill：真实IIC、VDMA所有权、ARM/cache屏障和全状态oracle联调未复现。

下一步是将这些接口绑定到新SoC的实际寄存器/VDMA配置，明确不会覆盖HELD缓冲的采集模式及底层IIC有界事务，再进入获准的Vivado设计校验和100MHz实现。当前不可直接上板运行，100MHz只是未改动的目标，尚无新增时序或资源结果。
