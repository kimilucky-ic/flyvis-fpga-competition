## 为什么不是把 Fly 直接“塞进”现有 SNN

现有 SNN HLS 以事件包驱动 LIF：32 位 spike 包大致为 `[31:21] timestamp / [20:13] weight / [12:0] neuron_id`，PL 路由和 DMA 围绕该接口构建。Fly PN 则每个神经元有多个 18 位 Q8.10 状态 `v,n,q,s,u` 与 10 位 `fc`，还需输入电流和 PN 特有的分段更新、限幅及发放规则。接口、状态和计算语义均不同，不能只换个参数或只替换权重表。

另外，现有 SNN 的 BRAM 已接近用尽；把完整权重型 SNN 与完整 Fly 网络并排塞入当前设计没有可用的 BRAM 余量。须选择“替换/裁剪现有计算核”或“另做最小独立 Fly bitstream”之一，不能默认叠加。

## 推荐的真正移植路线

1. **先校准真实方程。** 以完整网络正在实例化的 `PQN_PN.vhd` 为准，新增 Python `pqn_pn_reference`；用原始 VHDL 定点切片、限幅、状态更新和 spike crossing 建立固定向量。不要用当前 `DSSN_PN` 测试模型冒充生产 PN。
2. **做单 PN HLS 硬件核。** 用 `ap_int<18>`/`ap_uint<10>` 实现一次 PN 状态更新；HLS 顶层提供 AXI-Lite 输入/输出寄存器与 `ap_start/ap_done`。单步请求输入 I/v/n/q/s/u/fc，读回 v/n/q/s/u/fc 与 spike。先只做一个 PN，不放网络连接表或大数组。
3. **C 仿真和综合。** 用同一固定向量逐项对照 Python reference；要求所有状态位、fc、spike 精确一致。Vitis HLS 综合后检查 LUT/FF/BRAM/DSP、延迟、时钟估算；目标单 PN 状态应优先放寄存器，避免额外 BRAM。
4. **单独做最小 Zynq PS + PN AXI-Lite 设计。** 输出到新的 build/output 目录，保留现有 SNN BIT/HWH 不变；先用 PS/Jupyter 写寄存器、启动、读回，证明真正的 PL PN 核被调用。这个版本用于板上硬件证据，不等于完整 Fly 网络。
5. **扩成小网络后再决定合并。** 先 2–N 个 PN、明确状态 RAM 与突触/连接格式，估算 BRAM；根据资源结果选择替换当前 SNN 计算核或使用单独 Fly bitstream。最后再把气味传感器数据编码和行为输出映射进网络。
