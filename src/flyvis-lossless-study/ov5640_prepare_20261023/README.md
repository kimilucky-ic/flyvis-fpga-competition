## 已完成

- `inspect_vendor.py`只读取用户提供的官方ZIP中5项源码/约束/示例，保留成员SHA256、路径和原始版权头。未展开整包、未执行Notebook、未复制或加载官方摄像头BIT。`vendor_reference`仅作内部参考，不作独立许可或公开发布声明。
- `ps_input.py`是NumPy独立预处理原型，不导入Torch/PYNQ、不访问设备。保留现有full-field几何：保持长宽比缩放到417方形视场、背景0.5、13×13均值、原顺序721感受器、无镜像/旋转/自动对比度。RGB565按官方补零规则扩展。
- `verify_cpu.py`以原`camera_pipeline/adapter.py`及原BoxEye为CPU参考，640×480和800×600各6图：黑、白、红、XY渐变、棋盘格、固定随机。全部721项逐项比较，预设绝对误差阈值3e-6；实际最大6.854534149169922e-7。另有65,536像素Pillow灰度逐位核验、721坐标完全一致、BGR/GBR显式顺序测试、9项非法配置/帧拒绝测试。耗时22.824秒，Torch为CPU版本。
- `verify_target.py`为后续ARM验证入口，只需要NumPy和本目录冻结参考向量，不接触PYNQ、摄像头、寄存器或神经计算。当前仅在Windows CPU运行过，不能代替ARM验证。单帧约9–11ms的主机结果不可推算Cortex-A9帧率。
- `CPU_RESULT.json`记录版本、参考源SHA、逐项误差和时间；`CPU.log`为原始输出；`*_actual.npy`/`*_official.npy`保留721项FP32。`BASELINE_CHECK.json`核验四份旧封存版本全部成员。

预处理与Torch之间存在浮点舍入差异，**不宣称位等价输入**。该近似只属于相机输入构建，不改变神经算术。后续每一步保存实际输入位串，严格FP32神经CPU参考与PL必须消费同一实际输入，再逐位比较全部45,669状态。不能把本预处理对照当作神经多步正确性证明。

## 最小集成路径（尚未生成或验证新SoC）

1. 复用独立DDR SoC的完整神经模块、HP0写入和append-only验收日志；不修改已封存目录。
2. 摄像头独立DVP前端→官方异步video-in桥→仅采集方向VDMA→DDR。为相机采用独立HP1是当前集成建议；须在新候选中确认IP参数、地址和仲裁，不宣称已连接或综合通过。复用GP0控制总线接AXI IIC/VDMA；省去LCD、HDMI及MM2S显示链。
3. PS只读取已完成且被持有的帧；确保VDMA在读取期间不覆盖该缓冲，处理cache invalidate及内存顺序。原始帧、源帧序号、取帧时刻与实际721项输入一一对应。不得直接处理仍在写入的循环缓冲区。
4. 输入完整写入既有721字接口后才允许STEP，旧状态反馈留在PL。显示跳旧帧不改变神经步号，不删除神经输入/状态日志。摄像头未被选中用于STEP的原始帧可以跳过；每个已选输入和每个已完成神经步必须保留。容量到限先停，再开始下一步，错误/不确定状态不得自动重试/复位/释放内存。
5. PC只显示已发布记录。板端离线记录负责完整验收，不把PC界面列入神经递推关键路径。模型dt仍0.005s，不把摄像头帧率或板端吞吐伪称为200Hz模型实时。

## 官方源发现及待解决项

详见`VENDOR_INSPECTION.json`与保留原始源码，均不是实物引脚确认。

- 官方DVP数据口为8位，RGB565两字节；扩展白色为RGB(248,252,248)。示例显示前交换通道，不能默认VDMA字节为RGB。原型支持显式RGB/BGR/GBR，最终顺序必须用真实传感器色条独立验证。
- `cmos_capture_data.v`复位分支两次赋值`rst_n_d0`，未清零`rst_n_syn`。这是源码缺陷发现，不是已经修复的候选；集成时只在新副本中修正，并验证异步断言、同步释放、PCLK停止及启停后的完整首帧。
- 官方有`CLOCK_DEDICATED_ROUTE FALSE`例外；不把该约束视为时序通过。PCLK频率、输入时序预算、专用路由及异步CDC必须在新工程检查，不能只保留FCLK100MHz约束。
- 官方实例依赖`pynq.lib.ov5640.OV5640`、`pynq.lib.video2lcd`。目前源ZIP及资料目录中未找到独立OV5640 Python驱动。须补齐/定位传感器寄存器初始化和输出模式配置；不能以导入成功或IIC地址0x3c代替芯片ID、格式、时钟及分辨率验证。
- 资料同时含V3.9和旧V3.7底板。当前摄像头引脚依据主目录官方XDC，尚未独立确认实物底板版本和相机模块时钟来源，不能据此上板。
- 当前DDR工程已用102/140 BRAM36，余38块约171KiB。640×480 RGB888一帧921,600字节，必须放DDR。若3个采集缓冲约2.637MiB；485步神经日志87.148MiB另计，不共用或覆盖。
- 仅按640×480 RGB888×30fps举例，相机写DDR约27.648MB/s，PS若读取每帧又约27.648MB/s，均不含突发效率、cache和中间数组；神经日志另计。30fps只是预算场景，不是已配置/实测模式。当前没有camera IP的映射资源、DDR竞争或100MHz新时序报告。

## 复现（仅本地CPU）

在本目录以现有fly Python环境运行`inspect_vendor.py`和`verify_cpu.py`；前者需用户原始官方ZIP路径。CPU验证不启动GPU、摄像头、GUI、Vivado或网络连接。原始命令在`COMMANDS.json`。

未来ARM软件测试可执行`python3 verify_target.py 新结果路径.json`，需要先由用户另行安排板端文件与执行窗口；脚本不授权连接或硬件操作。不得把Windows结果改标签为ARM结果。
